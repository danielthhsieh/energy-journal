# F2 規格：補登前幾天

> 上游：[prd-directions-2026-09.md](prd-directions-2026-09.md) 第 4 節 F2
> 前置：F0（跳過）、F1（週回顧分頁）已上線
> 狀態：已開發（2026-09-06）。D2～D4 依 Daniel 指示改為獨立分頁，見第 11 節。

---

## 1. 目的

讓「當天沒記」不等於「這筆永遠沒了」。一次漏記不該引發整段放棄。做法只有一件事：允許表單的日期不是今天。

## 2. 判準對照（開發前必過）

| 判準 | 本規格的邊界 |
|---|---|
| C3 補登不能有欠債感 | **不列出哪些天沒填**。日期選擇器上沒有任何「有／無資料」的標記。只是可以換日期。 |
| C1 不呈現達成率 | 選擇器不出現計數、不出現「還有 N 天」 |
| C2 不催促 | 選擇器預設收合，不主動彈出 |
| 文案 | 禁用：漏、忘、缺、還沒、欠。「補登」作為分頁名稱由 Daniel 指定，保留；其餘處不用「補」字。 |

⚠️ F1 的密度點對「有資料的日子」畫實心點，在回顧脈絡下可接受。但同樣的標記放在日期選擇器上，就變成「請把空的填滿」。**兩處刻意不一致。**

## 3. 設計決策

| # | 決策 | 選擇 | 理由 |
|---|---|---|---|
| D1 | 可選範圍 | **今天與往前 6 天，共 7 天**。不可選未來。 | 一週內的記憶還可信。更早的補登會變成憑印象編分數。 |
| D2 | 選擇器形式 | **獨立分頁「補登」**，選單列中間第二顆按鈕。分頁內是 7 列日期（週幾 + 月/日），今天在最下並標「今天」。點一列 → 選定該日並切回日誌分頁。 | Daniel 指定。分頁形式讓補登是一個明確的「去別天」動作，不干擾日誌畫面。 |
| D3 | 選擇器預設 | 不在日誌分頁出現任何選擇器。 | 同 C2。 |
| D4 | 選了非今天的日子 | 標題顯示該日期，下方多一行淡色「回到今天」可點。主按鈕文字改為「完成這天的紀錄 ✨」，跳過按鈕改為「這天不記分數，只留個記號」。 | 使用者要隨時知道自己不在今天，避免誤寫。 |
| D5 | 切換日期時 | **先把表單重置為空白狀態**（滑桿 5、活動全關、文字清空、跳過狀態解除），再載入該日資料預填。 | 既有 `loadTodayRecord` 只設有值的欄位、不清舊值。不重置會把前一天的活動帶到下一天。 |
| D6 | 非今天送出成功後 | 成功 modal 關閉時**自動回到今天**並重新載入今天資料。 | 補登是一次繞路，結束就回主線。停留在過去日期容易接著誤寫。 |
| D7 | 送出後的週回顧 | 任一送出成功後，背景重新拉一次區間資料。 | 有了分頁後，補完立刻切去看回顧是自然動作，不該看到舊圖。F1 規格 6.6「不即時更新」據此修正。 |
| D8 | 後端 | **不改**。`?date=` 已支援任意日期；`doPost` 依日期覆蓋既有列。 | 依 PRD。未來日期由前端阻擋即可，Sheet 有全年預填列，即使誤送也只是寫進未來的列。 |
| D9 | 成功文案 | 非今天：標題「記下了」、內文「這一天也留下了」。跳過：標題「記號留下了」、內文「這天不記分數<br>也是一種選擇」。 | 不用「補」字。 |

## 4. 版面

```
┌─────────────────────────────────────┐
│  2026年9月4日 星期五        ▾        │   ← h1 可點，展開/收合
│  回到今天                            │   ← 只在非今天出現
│  ✓ 已載入這天的記錄                   │
│                                     │
│  [週日 8/31] [週一 9/1] [週二 9/2]    │   ← chip 列，展開時才出現
│  [週三 9/3] [週四 9/4●] [週五 9/5]    │      ● 只標「目前選的」，不標有無資料
│  [週六 9/6 今天]                      │
├─────────────────────────────────────┤
│  心理狀態（既有）                      │
```

- chip 用既有 `.activity-btn` 的視覺語言縮小版：淡邊框、選中時橘色邊框。
- 今天那顆 chip 多一個「今天」小字。
- chip 列展開時不推擠內容跳動太多：用 max-height 過渡。

## 5. 前端改動

### 5.1 狀態

```javascript
state.date = getTaiwanDate();   // 目前選定日期 yyyy-MM-dd
state.pickerOpen = false;
```

### 5.2 函式改動

| 函式 | 改法 |
|---|---|
| `updateDate()` | 改為顯示 `state.date`；非今天時顯示「回到今天」列 |
| `loadTodayRecord()` | 改名 `loadRecord(dateStr)`；載入前先 `resetFormState()`；載入指示文字：今天「✓ 已載入今日記錄」、非今天「✓ 已載入這天的記錄」、無資料「準備好了 ✨」 |
| `submitForm()` / `submitSkip()` | `date: state.date`；按鈕文字依是否今天切換；成功後若非今天 → modal 關閉時 `selectDate(today)` |
| `showSuccess()` | 接受第三個參數 `onClose`，modal 關閉時呼叫 |
| `resetForm()` | 按鈕文字依 `state.date` 是否今天決定 |
| 新增 `resetFormState()` | 滑桿歸 5、活動關、文字清空、`state.skip=false`、移除 `muted` |
| 新增 `selectDate(dateStr)` | 設 `state.date`、收合 picker、`updateDate()`、`loadRecord()` |
| 新增 `togglePicker()` / `renderPicker()` | 產生 7 顆 chip，標記選中者 |
| 送出成功處 | 呼叫 `loadWeeklyReview()`（D7） |

### 5.3 邊界

- chip 只產生 `[今天-6, 今天]`。`selectDate` 對範圍外的值直接忽略。
- 跨日：頁面開著跨過午夜，`getTaiwanDate()` 會變。送出時以 `state.date` 為準，不重算。若使用者在 23:59 開頁、00:01 送出，寫入的是開頁那天，符合「晚間記錄」的直覺。
- 週回顧的 `from/to` 仍以真實今天計算，與 `state.date` 無關。

## 7. 驗收條件

- [ ] 點日期標題展開 7 顆 chip，最右為今天且標「今天」；再點收合。
- [ ] chip 上沒有任何有無資料的標記；全頁搜尋不到「補、漏、忘、缺、還沒、欠」。
- [ ] 選 9/4：標題變 9/4、出現「回到今天」、表單先清空再預填 9/4 資料（若有）。
- [ ] 在 9/4 勾了散步後切到 9/5：散步為關（D5）。
- [ ] 在 9/4 送出一般記錄：payload `date` 為 9/4；Sheet 9/4 列被寫入；modal 文案為「記下了」；modal 關閉後回到今天並載入今天資料。
- [ ] 在 9/4 送出跳過：Sheet 9/4 列 K 為 TRUE、分數空白；modal 關閉後回到今天。
- [ ] 送出成功後切到週回顧分頁，密度點已反映剛寫入的那天（D7）。
- [ ] 今天送出的行為與文案與 F0 上線版完全相同。
- [ ] 無法選到明天或 8 天前。
- [ ] 手機寬度下 chip 列不溢出、可換行。

## 8. 觀察者側指標（不進前端）

| 指標 | 定義 |
|---|---|
| 補登比例 | 送出日期 ≠ 送出當日的筆數 / 全部筆數。⚠️ Sheet 沒有「送出時間」欄，目前**量不到**。若想量，需後端在 L 欄之後另找位置寫 timestamp，但 L/M 被摘要佔用。**v1 不量**，記在此處供日後決定。 |

## 9. 範圍外

- 不做超過 7 天的補登。
- 不做批次補登、不做「這幾天都跳過」。
- 不做送出時間戳。
- 不改後端。

## 11. 選單列改為不固定（同批變更）

Daniel 回報：固定在底部的選單列在 iPhone 16 Pro 的 Safari 上吃掉太多可視高度。改法：

- 選單列改為**跟著內容排在頁面最底部**，不再 `position: fixed`。滑到最下方才看得到。
- 外層 `.app` 設 `min-height: calc(100dvh - 40px - env(safe-area-inset-bottom))`，用動態視窗高度撐住，短內容的分頁（例如週回顧空狀態）選單列也會落在第一屏之下、而不是浮在畫面中間。`100vh` 為舊瀏覽器備援。
- 移除原本為固定列預留的 body 底部 96px。
- 切換分頁後捲回頂端，所以每次切換都要再滑到底才能換下一個分頁。這是這個設計的代價，Daniel 知情。
