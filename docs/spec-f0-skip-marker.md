# F0 規格：「今天不記分數」跳過標記

> 上游：[prd-directions-2026-09.md](prd-directions-2026-09.md) 第 4 節 F0
> 狀態：已開發（2026-09-06），待部署後端與 Sheet 驗收
> 決策（2026-09-06，Daniel）：跳過模式**允許填活動、不填分數**。

---

## 1. 目的

讓「我今天選擇不記分數」成為一筆可被記錄的資料，而不是一列空白。這樣「刻意減量」與「不小心停掉」在 Sheet 上才分得開，後續週回顧（F1）與提醒（F3）才有正確的分母。

## 2. 語意定義

一筆「跳過」記錄的定義：

| 欄位 | 值 | 說明 |
|---|---|---|
| 日期 | 該日 | 與一般記錄相同 |
| 跳過 | `TRUE` | 新增欄位 |
| 壓力分數、思路清晰度、睡前電量 | **空白** | 不是 0、不是 5、不是任何數字 |
| 散步、冥想、重訓、跑步 | 使用者當下勾選的狀態 | 有做就 TRUE，沒做就 FALSE，與一般記錄相同 |
| 輕量感恩、反思 | 使用者當下輸入的內容，可為空 | 不強制、不阻擋 |

**三種狀態在資料上的區別**：

| 狀態 | 分數欄 | 跳過欄 | 解讀 |
|---|---|---|---|
| 一般記錄 | 有值 | `FALSE` 或空 | 正常登記 |
| 跳過 | 空 | `TRUE` | 刻意不記分數 |
| 未登記 | 空 | 空 | 沒有進系統（漏掉或停用） |

**互斥規則**：同一日期只能是「一般記錄」或「跳過」其一。後送出的覆蓋先送出的。
- 一般送出 → 寫入三個分數，並將跳過設為 `FALSE`。
- 跳過送出 → 三個分數寫成空白，並將跳過設為 `TRUE`。

## 3. 資料層：Google Sheet

### 3.1 新增欄位

在「能量日誌」工作表第 1 列新增標題 **`跳過`**，位置為 **K 欄**（第 11 欄，緊接「反思」之後）。

理由：目前 CSV 顯示 K 欄為空，L、M 欄放月份摘要（總天數、高壓日、平均思緒分數）。放在 K 欄不會碰到既有摘要。

### 3.2 既有列的預設值

不回填。2026 全年預填的日期列，跳過欄維持空白。空白視同 `FALSE`。

### 3.3 對側欄摘要公式的影響

- 「平均思緒分數」等 AVERAGE 類公式：分數欄寫入的是真正的空白儲存格，不是空字串，AVERAGE 會自動忽略。
- 「高壓日」等 COUNTIF 類公式：不受影響。
- 若日後要算「有資料天數」，公式為 `分數非空 OR 跳過=TRUE`。這屬於 F1，本規格不動側欄。

⚠️ 後端寫入空白時必須用真正的空值（Apps Script 中 `setValue("")` 會產生空儲存格），**不可寫 0**。寫 0 會被 AVERAGE 吃進去，把刻意不記變成一個假的低分。

## 4. 後端：Google Apps Script

> `energy-journal.gs` 目前不在 repo 內。以下為需要達成的行為與參考片段，實作前先把現有檔案納入版控（見第 9 節）。

### 4.1 `doPost` 變更

接受 payload 中新增的布林欄位 `跳過`。

```javascript
// 參考片段：組出要寫入的一列
const skip = data.跳過 === true;

const row = [
  data.date,
  skip ? "" : data.壓力分數,
  skip ? "" : data.思路清晰度,
  skip ? "" : data.睡前電量,
  data.散步 === true,
  data.冥想 === true,
  data.重訓 === true,
  data.跑步 === true,
  data.輕量感恩 || "",
  data.反思 || "",
  skip            // K 欄：跳過
];
```

覆蓋既有日期列時，整列 A 到 K 都要重寫，確保「一般送出」會把跳過清回 `FALSE`、「跳過送出」會把分數清成空白。

### 4.2 `doGet` 變更

`?date=YYYY-MM-DD` 的回傳 `data` 物件多一個欄位：

```json
{ "success": true, "found": true,
  "data": { "日期": "...", "壓力分數": "", "思路清晰度": "", "睡前電量": "",
            "散步": true, "冥想": false, "重訓": false, "跑步": false,
            "輕量感恩": "", "反思": "", "跳過": true } }
```

`跳過` 讀取時：儲存格為 `TRUE` 回 `true`，其他一律回 `false`。

### 4.3 相容性

前端舊版（沒送 `跳過` 欄位）打進來時，`data.跳過` 為 `undefined`，`skip` 為 `false`，行為與現在完全相同。

## 5. 前端：`index.html`

### 5.1 新增元件

在 `#submitBtn`（「完成今晚的紀錄 ✨」）**下方**新增一顆次要按鈕：

```html
<button class="skip-btn" id="skipBtn" onclick="submitSkip()">今天不記分數，只留個記號</button>
```

視覺要求：
- 純文字或極淡底色，字級小於主按鈕，對比度低於主按鈕。它必須看起來像「另一個合法選項」，不能像警告，也不能像被鼓勵的選項。
- 不加 emoji，不加驚嘆號。
- 深色與淺色主題各自定義顏色。

### 5.2 `state` 新增

```javascript
skip: false   // 該日期目前是否為跳過狀態（由 loadTodayRecord 填入）
```

### 5.3 `submitSkip()` 行為

1. 若 `state.submitting` 為 true，直接 return。
2. 不彈確認對話框。一次點擊即送出。
3. payload：

```javascript
{
  date: today,
  跳過: true,
  壓力分數: null, 思路清晰度: null, 睡前電量: null,
  散步: state.walk, 冥想: state.meditate, 重訓: state.strength, 跑步: state.run,
  輕量感恩: state.gratitude, 反思: state.reflection
}
```

4. 送出期間兩顆按鈕同時 disabled，`#skipBtn` 文字改為「正在留記號⋯」。
5. 成功後顯示成功 modal，文字為 **「記號留下了」**，不使用「完成」「達成」等字。3 秒後自動關閉，與現有行為一致。
6. 失敗時沿用 `showError()`。

### 5.4 `submitForm()` 變更

payload 新增 `跳過: false`。其餘不變。

### 5.5 `loadTodayRecord()` 變更

當 `result.data.跳過 === true`：
- `state.skip = true`
- **不**把滑桿設值（分數為空，滑桿維持預設 5，但顯示上要讓使用者知道這不是資料）。
- 活動按鈕、文字欄照常預填。
- `#loadIndicator` 文字改為 **「今天已留記號」**，加 `done` class。
- 三個滑桿區塊加上 class `muted`（降低不透明度），代表「目前沒有分數資料」。使用者一旦拖動任何滑桿，移除 `muted`，`state.skip = false`。

當 `跳過` 為 false 或不存在：行為與現在相同。

### 5.6 從跳過改回一般記錄

使用者在「今天已留記號」狀態下拖動滑桿後按主按鈕，即為一般送出，後端會覆蓋並把跳過清回 `FALSE`。不需要額外的「取消記號」功能。

## 6. 文案

## 8. 驗收條件

- [ ] Sheet K1 為「跳過」，L、M 欄摘要未被移動。
- [ ] 點擊跳過按鈕一次，該日期列：三個分數欄為**空儲存格**（用 `ISBLANK` 驗證為 TRUE），K 欄為 `TRUE`，活動欄反映當下勾選。
- [ ] 同日先跳過、再拖滑桿送一般記錄：分數有值，K 欄為 `FALSE`。

- [ ] 重新載入頁面，已跳過的日期顯示「今天已留記號」，滑桿區塊為 `muted`，活動按鈕正確預填。
- [ ] 拖動任一滑桿後 `muted` 移除。
- [ ] 舊版前端（未送 `跳過`）打新版後端，行為不變。
- [ ] 側欄「平均思緒分數」在新增一筆跳過後數值不變。
- [ ] 深色與淺色主題下跳過按鈕對比度皆低於主按鈕。

## 10. 範圍外

- 不做「為什麼不記」原因欄。
- 不做批次跳過（一次標記多天）。那是 F2 補登開放日期後才有的情境，且要另過 C3。
- 不做跳過的統計或呈現。屬於 F1。
- 不修 `no-cors` 假成功問題。屬於 F4，但建議與本規格一起改 `.gs` 時順手處理，因為兩者都要重新部署後端。
